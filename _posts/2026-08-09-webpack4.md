## 前言
从 ``webpack4`` 开始， ``wepback`` 内置的 CLI 命令工具被剥离出来，形成了的独立的包 ``webpack-cli`` 需要单独安装。

1\. ``webpack`` 和 ``webpack-cli`` 的版本对应关系。

| webpack | webpack-cli |
| :-: | :-: | :-: |
| 3.x | / |
| 4.x | 3.x |
| 5.x | 4.x \|\| 5.x |

2\. ``webpack-cli`` 对应的 ``nodejs`` 和 ``webpack`` 的版本对应关系。

| webpack-cli | nodejs | webpack |
| :-: | :-: | :- |
| 3.x | >= 6.11.5 | 专门服务于 4.x |
| 4.x | >= 10.13.0 | 5.x 初期过渡版本，开始弃用旧的 nodejs |
| 5.x | >= 14.15.0 | 专门服务于 5.x |
| 6.x | >= 18.12.0 | >= 5.82.0 |
| 7.x | >= 20.9.0 | >= 5.101.0 |

3\. ``webpack`` 与 ``babel`` 系列包的版本对应关系。

| webpack | babel-loader | babel-core | babel-preset-env | @babel/core | @babel/preset‑env | 
| :-: | :- | :- |
| 3.x | 7.x | 6.x | 1.x | / | / |
| 4.x | 8.x | / | / | 7.x | 7.x |
| 5.x | 8.x/9.x | / | / | 7.x/^7.12.x | 7.x/^7.12.x |

### public目录
1\. ``favicon.ico`` 网站的头像，格式为 ``.ico`` 格式，可通过免费的在线生成网站制作[‌ICO5.net](https://ico5.net/)，然后在 ``index.html`` 文件中配置 ``<link rel="icon" href="./favicon.ico">`` 。

![webapck4_01](/static/img/webpack4/webpack4_01.jpg)

2\. ``index.html`` 
```html
<!doctype html>
<html>
<head>
  <meta charset="utf-8">
  <meta http-equiv="X-UA-Compatible" content="IE=edge,chrome=1">
  <meta name="viewport" content="width=device-width,initial-scale=1,minimum-scale=1,maximum-scale=1,user-scalable=no" />
  <link rel="icon" href="./favicon.ico">
  <title>index</title>
</head>
<body>
  <script src="/main.js" type="text/javascript"></script>
</body>
</html>
```
> + ``<!doctype html>`` : ``html5`` 文档声明，用途告诉浏览器如何渲染整个 ``html`` 文档（ ``html4`` 文档声明比较老了，不作介绍）。
+ ``<meta charset="utf-8">`` :  告诉浏览器使用什么编码渲染浏览器的字符，当然文档自身也要是 ``utf-8`` 编码保存的。
+ ``<meta http-equiv="X-UA-Compatible" content="IE=edge,chrome=1">`` : 专门针对旧 IE 浏览器，强制 IE 使用最高版本渲染模式；有 Chrome 内核时优先使用 Chrome 内核。。
+ ``  <meta name="viewport" content="width=device-width,initial-scale=1,minimum-scale=1,maximum-scale=1,user-scalable=no" />`` : 设置移动端禁止网页缩放。
+ ``<link rel="icon" href="./favicon.ico">`` : 网站头像，浏览器选项卡左上角展示的 ``icon`` 。
+ ``<title>index</title>`` : 浏览器选项卡的名称。
+ ``<script src="/main.js" type="text/javascript"></script>`` : ``webpack`` 的入口文件的引用。

+  配置启动本地 ``http`` 服务命令

```json
"scripts": {
  "dev": "webpack-dev-server --env NODE_ENV=development --mode development",
  "build:test": "webpack --env NODE_ENV=test --mode production",
  "build:production": "webpack --env NODE_ENV=production --mode production",

```
> 当前配置的 ``--env NODE_ENV=`` 的方式后续会在 ``webpack.config.js`` 的函数中通过 ``plugin`` 配置重写 ``process.env.NODE_ENV`` 的值。


其他配置 ``--env`` 的传参方式
```json
"scripts": {
  // 这种配置方式传递给导出函数的第一个入参形式为 { development: true }
  "dev": "webpack-dev-server --env development --mode development",
  // 这种配置方式传递给导出函数的第一个入参形式为 { development: "env" }
  "dev": "webpack-dev-server --env development=test --mode development",
  // 这种配置方式传递给导出函数的第一个入参形式为 { key1: "value1", key2: true }
  "dev": "webpack-dev-server --env.key1=value1 --env.key2 --mode development",
}
```






### webpack.config.js
- 完整配置

```javascript
const webpack = require('webpack');
const path = require('path');
const config = {
  // 命令行的传递 --mode production 优先级高于配置文件
  // mode: 'development',

  // 入口文件配置
  entry: './src/main.js', // 指定你的应用入口文件
  
  // 输出配置
  output: {
    path: path.resolve(__dirname, 'dist'), // 输出文件的路径，绝对路径
    publicPath: '/',
    filename: '[name].js', // 输出文件的名称
    chunkFilename: '[id][chunkhash].chunk.js'
    // assetModuleFilename: 'assets/[name].[hash:8][ext]'
  },
  
  // 开发工具配置，用于source map等
  // devtool: 'inline-source-map',
  
  // 模块配置
  module: {
    rules: [
      {
        test: /\.js$/, // 使用正则表达式来匹配需要处理的文件类型
        exclude: /node_modules/, // 排除node_modules目录下的文件，提高构建效率
        use: ['babel-loader']
      },
      {
        test: /\.css$/, // 处理CSS文件
        use: ['style-loader', 'css-loader'] // 使用style-loader和css-loader来处理CSS文件
      }
    ]
  },
  
  // 解析配置，帮助Webpack找到模块的路径和扩展名等
  // resolve: {
  //   extensions: ['.js', '.json', '.css'] // 自动解析确定的扩展
  // },
  
  // 插件配置，这里不使用插件的例子，如果需要可以添加相关插件配置代码块
  plugins: [], // 在这里可以添加各种Webpack插件，例如HtmlWebpackPlugin等
  
  // 开发服务器配置，用于开发环境下的实时重载等
  devServer: {
    // contentBase: '/public', // 指定开发服务器的基础路径
    port: 8181, // 服务端口
    host: 'localhost',
    hotOnly: false, // 只热更新，不自动刷新浏览器
    hot: true, // 启用模块热替换功能
    historyApiFallback: true, // 访问404时，回退到index.html，SPA路由必开
    compress: true, // 是否压缩
    proxy: {
      '/api': {
        target: 'http://127.0.0.1:8888',
        changeOrigin: true, // 修改当前请求的请求源为目标源，解决跨域，绝大多数场景必须开启
        secur: false, // 后端https证书无效/自签名证书，设置false跳过校验
        ws: true, // 如果要代理 websocket
        pathRewrite: {
          '^/api': ''
        }
      }
    }
  }
};

// env 参数是 ``package.json`` 的 
module.exports = (env, argv) => {
  config.plugins.push(
    new webpack.DefinePlugin({
      'process.env.NODE_ENV': JSON.stringify(env.NODE_ENV)
    })
  );

  return config;
};
```
> + 基本配置方式，需要一个基础的配置对象，配置入口、出口、插件、本地服务等。再通过导出函数的入参进行动态修改配置参数。
+ 导出函数的入参
  + ``env`` : ``--env`` 传递的值。
  + ``argv`` : ``webpack-cli`` 解析后的全部命令行选项对象，具体如下:
  : | argv字段 | 对应CLI参数 | 类型 | 说明 |
| :-: | :-: | :-: | :-: |
| `mode` | `--mode` | string / undefined | `development`/`production`；**命令行不传就是undefined**，此时webpack4报mode警告 |
| `watch` | `--watch,-w` | boolean | 文件监听模式 |
| `config` | `--config` | string | 当前加载的配置文件路径 |
| `hot` | `--hot` | boolean | HMR热模块替换 |
| `stats` | `--stats` | string/boolean | 控制台输出级别：`errors-only`、`minimal`、`verbose` |
| `progress` | `--progress` | boolean/string | 打包进度打印；`--progress=profile`可输出性能剖析 |
| `profile` | `--profile` | boolean | 输出每个模块编译耗时 |
| `json` | `--json,-j` | boolean/string | 输出stats json，可传入文件路径输出到磁盘 |
| `analyze` | `--analyze` | boolean | 唤起webpack‑bundle‑analyzer（需要已安装） |
| `failOnWarnings` | `--fail‑on‑warnings` | boolean | 警告也让进程返回非0退出码 |
| `version` | `--version,-v` | boolean | 输出版本号，此时不会执行打包 |
| `help` | `--help` | boolean | 输出帮助信息 |

<br />

+ mode - 开发模式
  - 值: ``none|developent|production`` ，默认值为 ``production`` 。
  - 用途: 对 ``webpack`` 进行预设配置。
        - 环境变量注入: 自动通过 ``DefinePlugin`` 将 ``process.env.NODE_ENV`` 替换为对应字符串（ ``"development"``  或  ``"production"`` ）。
        - 插件自动启用: 无需手动配置 ``plugins`` 数组， ``Webpack`` 内部自动实例化特定优化插件。
        - 优化项开关‌: 控制 ``optimization`` 下的压缩、模块串联、代码分割等策略默认值。
        - 其他默认覆盖: 影响 ``devtool`` 、 ``cache`` 、 ``output.pathinfo`` 、 ``performance.hints`` 等全局配置。‌‌

> + 如果设置为 ``none`` ，禁用所有基于 ``mode`` 的默认绣花和产检，需要完全手动配置。
+ 关于 ``process.env.NODE_ENV``介绍
  + 来源: 属于 ``nodejs`` 的内置环境变量。
  + 修改方式
    + 通过安装 ``cross-env`` 修改
      + ``npm install cross-env --save-dev``
      + 给 ``package.json`` 的 ``scripts`` 运行命令，增加 ``cross-env NODE_ENV=development npx webpack-dev-server --env NODE_ENV=development --mode development`` 参数，配置完成后，可以在 ``webapck.config.js`` 通过 ``console.log(process.env.NODE_ENV)`` 打印，重新启动 ``npm run dev`` 后查看打印结果。
    + 终端命令设置（临时有效）
      + ``cmd`` : ``set NODE_ENV=production && npx webpack-dev-server --env NODE_ENV=development --mode development``。
      + ``powershell`` : ``$env:NODE_ENV="production"; npx webpack-dev-server --env NODE_ENV=development --mode development``。
  + 在 ``webpack`` 开发模式下，只有配置文件 ``webpack.config.js`` 未被 ``webpack`` 接管，所以输出的是原始的变量，在入口文件输出的是 ``webapck`` 的 ``DefinePlugin`` 构造的全局 ``js`` 变量。
+ 由于 ``--mode`` 会默认修改 ``process.env.NODE_ENV`` ，且参数类型有限，需要通过 ``--env`` 注入参数后修改 ``process.env.NODE_ENV`` 的值满足使用要求。
```javascript
// 通过 --env 参数来修改 process.env.NODE_ENV 变量
plugins: [
  new webpack.DefinePlugin({
    'process.env.NODE_ENV': JSON.stringify(env.production ? 'production' : 'development')
  })
]
```
+ ``mode`` 的配置优先级，命令行 ``--mode production`` 的配置方式大于 ``webpack.config.js`` 的配置。
