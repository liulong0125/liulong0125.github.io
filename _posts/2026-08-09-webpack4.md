## 前言
从 ``webpack4`` 开始， ``wepback`` 内置的 CLI 命令工具被剥离出来，形成了的独立的包 ``webpack-cli`` 需要单独安装。

1\. ``webpack`` 和 ``webpack-cli`` 的版本对应关系。

| webpack | webpack-cli |
| :-: | :-: | :-: |
| 3.x | / |
| 4.x | 3.x |
| 5.x | 4.x \|\| 5.x |

2\. ``webpack-cli`` 对应的 ``nodejs`` 和 ``webpack`` 的版本对应关系。

| webpack-cli | nodejs | webpack |
| :-: | :-: | :- |
| 3.x | >= 6.11.5 | 专门服务于 4.x |
| 4.x | >= 10.13.0 | 5.x 初期过渡版本，开始弃用旧的 nodejs |
| 5.x | >= 14.15.0 | 专门服务于 5.x |
| 6.x | >= 18.12.0 | >= 5.82.0 |
| 7.x | >= 20.9.0 | >= 5.101.0 |

3\. ``webpack`` 与 ``babel`` 系列包的版本对应关系。

| webpack | babel-loader | babel-core | babel-preset-env | @babel/core | @babel/preset‑env | 
| :-: | :- | :- |
| 3.x | 7.x | 6.x | 1.x | / | / |
| 4.x | 8.x | / | / | 7.x | 7.x |
| 5.x | 8.x/9.x | / | / | 7.x/^7.12.x | 7.x/^7.12.x |




## 安装需要的包
```
// webpack & webpack-cli
npm install webpack@4.47.0 webpack-cli@3.3.12 --save-dev
// webpack-dev-server 配置本地 http 开发服务，对应的是 webpack.config.js 的 devServer 配置项）
npm install webpack-dev-server@3.7.2 --save-dev
// babel（es6+转换es5）相关包的安装
npm install babel-loader@8.4.1 "@babel/core@7.29.7" "@babel/preset-env@7.29.7" --save-dev
```



## 文件配置
初步配置目录结构如下:
```
├── public                        #本地 http 服务器的入口目录
|  ├── favicon.ico                #网站头像（非必要）浏览器选项卡展示的图标
|  └── index.html                 #索引文件
├── src                           #业务逻辑代码的入口目录
|  └── main.js                    #webpack 收集文件的依赖入口
├── package.json                  #依赖的包
└── webpack.config.js             #webpack配置文件
```



### public目录
1\. ``favicon.ico`` 网站的头像，格式为 ``.ico`` 格式，可通过免费的在线生成网站制作[‌ICO5.net](https://ico5.net/)，然后在 ``index.html`` 文件中配置 ``<link rel="icon" href="./favicon.ico">`` 。

2\. ``index.html`` 
```html
<!doctype html>
<html>
<head>
  <meta charset="utf-8">
  <meta http-equiv="X-UA-Compatible" content="IE=edge,chrome=1">
  <meta name="viewport" content="width=device-width,initial-scale=1,minimum-scale=1,maximum-scale=1,user-scalable=no" />
  <link rel="icon" href="./favicon.ico">
  <title>index</title>
</head>
<body>
  <script src="/main.js" type="text/javascript"></script>
</body>
</html>
```
> + ``<!doctype html>`` : ``html5`` 文档声明，用途告诉浏览器如何渲染整个 ``html`` 文档（ ``html4`` 文档声明比较老了，不作介绍）。
+ ``<meta charset="utf-8">`` :  告诉浏览器使用什么编码渲染浏览器的字符，当然文档自身也要是 ``utf-8`` 编码保存的。
+ ``<meta http-equiv="X-UA-Compatible" content="IE=edge,chrome=1">`` : 专门针对旧 IE 浏览器，强制 IE 使用最高版本渲染模式；有 Chrome 内核时优先使用 Chrome 内核。。
+ ``  <meta name="viewport" content="width=device-width,initial-scale=1,minimum-scale=1,maximum-scale=1,user-scalable=no" />`` : 设置移动端禁止网页缩放。
+ ``<link rel="icon" href="./favicon.ico">`` : 网站头像，浏览器选项卡左上角展示的 ``icon`` 。
+ ``<title>index</title>`` : 浏览器选项卡的名称。
+ ``<script src="/main.js" type="text/javascript"></script>`` : ``webpack`` 的入口文件的引用。

### package.json
配置启动本地 ``http`` 服务命令

```json
"scripts": {
  // 这种配置方式传递给导出函数的第一个入参形式为 { development: true }
  "dev": "webpack-dev-server --env development --mode development",
  // 这种配置方式传递给导出函数的第一个入参形式为 { development: "env" }
  "dev": "webpack-dev-server --env development=test --mode development",
  // 这种配置方式传递给导出函数的第一个入参形式为 { key1: "value1", key2: true }
  "dev": "webpack-dev-server --env.key1=value1 --env.key2 --mode development",
  "build:test": "webpack --mode production",
  "test": "echo \"Error: no test specified\" && exit 1"
}
```






### webpack.config.js
基本配置方式，需要一个基础的配置对象，配置入口、出口、插件、本地服务等。再通过导出函数的入参进行动态修改配置参数。


- 具体配置项


1. mode - 开发模式
  - 值: ``none|developent|production`` ，默认值为 ``production`` 。
  - 用途: 对 ``webpack`` 进行预设配置。
        - 环境变量注入: 自动通过 ``DefinePlugin`` 将 ``process.env.NODE_ENV`` 替换为对应字符串（ ``"development"``  或  ``"production"`` ）。
        - 插件自动启用: 无需手动配置 ``plugins`` 数组， ``Webpack`` 内部自动实例化特定优化插件。
        - 优化项开关‌: 控制 ``optimization`` 下的压缩、模块串联、代码分割等策略默认值。
        - 其他默认覆盖: 影响 ``devtool`` 、 ``cache`` 、 ``output.pathinfo`` 、 ``performance.hints`` 等全局配置。‌‌
> 如果设置为 ``none`` ，禁用所有基于 ``mode`` 的默认绣花和产检，需要完全手动配置。

由于 ``--mode`` 会默认修改 ``process.env.NODE_ENV`` ，且参数类型有限，需要通过 ``--env`` 注入参数后修改 ``process.env.NODE_ENV`` 的值满足使用要求。

```javascript
// 通过 --env 参数来修改 process.env.NODE_ENV 变量
plugins: [
  new webpack.DefinePlugin({
    'process.env.NODE_ENV': JSON.stringify(env.production ? 'production' : 'development')
  })
]
```
