## 前言
``Mermaid`` 是一个基于 ``JavaScript`` 的图表和作图工具，它使用类似 ``Markdown`` 的文本定义和渲染器来创建和修改复杂的图表。``Mermaid`` 的主要目的是帮助文档跟上开发的步伐。
[官网](https://mermaid.js.org/)、[中文学习网](https://docs.min2k.com/zh/mermaid/intro/)、[github](https://github.com/mermaid-js/mermaid)。

### 环境配置
在 ``jekyll`` 中使用  ``mermaid.js``，需要安装 ``jekyll-mermaid`` 插件。[官方安装示例](https://rubygems.org/gems/jekyll-mermaid)，由于[github插件支持白名单](https://docs.github.com/zh/pages/setting-up-a-github-pages-site-with-jekyll/about-github-pages-and-jekyll)中没有 ``jekyll-mermaid`` ，不能通过 ``gem install jekyll-mermaid`` 的方式安装，静态页会不生效，需要通过传统 ``<script>`` 标签的方式引入。

```html
<!-- 将改代码放到 js 代码统一执行的入口处，e.g. 当前静态页放到了 body 的结尾处  -->
<script type="module">
  import mermaid from 'https://cdn.jsdelivr.net/npm/mermaid@11/dist/mermaid.esm.min.mjs';
  
  // 关闭自动渲染逻辑（依托于 DOMContentLoaded 事件，此时无法修改默认的扫描元素类，需要手动调用 mermaid.run 进行掌控）
  mermaid.initialize({
    startOnLoad: false,
    markdownAutoWrap: true, // 默认值 true
    securityLevel: 'loose', // 允许触发节点的点击事件
    htmlLabels: true, // false -> svg 内的文字使用 <text> 标签渲染，true - 通过 <foreignObject> 标签嵌入 html 渲染文字（解决设置 markdown 格式问题，以及文字 markdownAutoWrap 文字折行能力
    flowchart: { // 流程图的单独配置
      useMaxWidth: true, // 适配博客容器，手机也能正常缩放
      curve: 'basis' // 连线方式, e.g. basis、bumpX、bumpY、cardinal、catmullRom、linear、monotoneX、monotoneY、natural、step、stepAfter和stepBefore
    }
  });

  // 由于 markdown 的解析器 kramdown（当前项目使用的解析器，常用的解析器e.g. kramdown、rdiscount、maruku），生成的元素的类名携带了 "language-" 前缀，需要使用 mermaid.run 方法修改元素选择器（高版本已经不支持在 mermaid.initialize 中设置了）
  await mermaid.run({ querySelector: '.language-mermaid' });
  console.log('图表渲染完成...');
</script>
```

### 流程图
流程图由节点（几何形状）和边（箭头或线条）组成。Mermaid 代码定义了节点和边的生成方式，并支持不同类型的箭头、多方向箭头以及与子图的任意链接。

#### 单节点
````
```mermaid
flowchart LR
  id[文本]
  节点2["`**加粗内容**`"]
  节点3["`行1
  
  行2

  行3`"]
```
````
```mermaid
flowchart LR
  id[文本]
  节点2["`**加粗内容**`"]
  节点3["`行1
  
  行2

  行3`"]
```

> + 使用  ``flowchart``/ ``graph`` 开头，紧跟着是流程图的布局方向。
+ "[文本]" 此内容为非必填，不填写就展示文本 ``id`` 。
+ 如果需要对节点文本使用 ``markdown`` 格式，需要使用  ``""``（双引号）将文本括起来，再使用 `` ` ``（反单引号）号将 ``markdown`` 格式内容括起来。

+ 布局方向

    + TD - 自上而下 / 与从上到下相同
    + BT - 从底部到顶部
    + RL - 从右到左
    + LR - 从左到右


+ **角色创建和销毁（V10.3.0+）**
````
```mermaid
sequenceDiagram
  小张->>小李: 还好吗？
  小李->>小张: 很好！

  create participant 小王

  小张-->>小王: 你好 小王!

  create actor D as 小赵
  
  小王->>D: 你好!

  destroy 小王

  小张-x小王: 再见！

  小李-->>小张: 回见！
```
````
```mermaid
sequenceDiagram
  小张->>小李: 还好吗？
  小李-->>小张: 很好！

  create participant 小王

  小张->>小王: 你好 小王!

  create actor D as 小赵
  
  小王->>D: 你好!

  destroy 小王

  小张-x小王: 再见！

  destroy 小李

  小李-->>小张: 回见！
```

> + `create` 和 `destory` 的渲染含义: 这是**UML 时序图对象生命周期语义**：普通 participant/actor 是在图表顶部一次性全部画出；`create` / `destroy` 用来表达**对象在交互过程中动态实例化、销毁**。
+ `create`
  + 渲染表现
    + 小王不会在时序图最上方一开始就出现。
    + 在 `小张-->>小王` 这条消息的位置，才把 小王的方框 + 生命线画出来。
    + 生命线从这条消息位置向下延伸，而不是从图表顶端开始。
  + 语义约束
    + `create` 只能创建**消息接收方**（不能创建发送方）。
    + 支持别名写法：`create actor D as 小赵`（D 是标识符，显示名称 小赵）。
+ `destroy`
  + 渲染表现
    + 在紧随其后的这条消息（`小张-x小王`）处，**终止 小王的生命线**。
    + 在生命线末端画一个叉号，标记对象生命周期结束，即便没有 `-x` 这条消息也是终止了，直观的视觉效果就是角色的下侧方块不会再向下延伸了，如果没有终止的话，小王的下方块会和小张的下方块处于平行线上，参照 `小赵` 没有被终结，就和小张下方区域平行对其了。
    + **v10.3 ~ v10.6 版本有 BUG**：如果写了 `destroy` 但是**后面没有跟着一条销毁消息（`-x`）**，会抛出报错：
`The destroyed participant XXX does not have an associated destroying message after its declaration`
升级到 **v10.7.0+** 修复了这个 BUG，允许单独写 `destroy X`，后面不跟消息，不再报错
  + 语义约束
    + destroy 可以销毁**消息发送方 或 接收方**（和 create 不一样）。
    + 箭头推荐用 `-x`（叉号箭头），UML 习惯代表销毁 / 删除消息。
    + **<font color=red>即使 destroy 之后，仍然可以继续写消息（Mermaid 不会阻止语法渲染），只是语义上代表：这条消息触发销毁动作。不是说销毁之后对象就彻底不能写消息了。</font>**




+ **分组/方框**
角色可以分组到垂直方框中。您可以定义颜色（如果没有，则为透明）和/或使用以下表示法定义描述性标签。语法对为 `box + [transparent] + [颜色] + 标题` ，结束 `end`。颜色为可选参数，如果碰巧的标题刚好是颜色名字，可以通过在颜色前面添加 transparent 让填充颜色透明，不影响标题的渲染。

````
```mermaid

  participant A
  participant J
  end

  box yellow 小组2
  participant B
  participant C
  end

  A->>J: 早上好！
  J->>A: 早!
  A->>B: 你好！
  B-->>C: 来了！
```
````

### 消息
消息可以显示为实线或虚线。

| 符号 | 线条样式 | UML/工程含义 | 业务场景举例 |
|---|---|---|---|
| `->` | 实线，无箭头 | 单纯依赖、关联，不是消息调用；仅表达两者存在关系 | 静态依赖标注，很少在动态时序交互中使用 |
| `-->` | 虚线，无箭头 | 弱依赖、关联；不带返回动作 | 极少用 |
| `->>` | 实线，实心箭头 | **同步调用**，发送方阻塞等待对方处理完成再继续（最常用） | HTTP请求、函数调用、RPC调用；配合`activate`激活条 |
| `-->>` | 虚线，实心箭头 | **返回响应**，同步调用的结果回传 | HTTP返回200、接口返回数据 |
| `<<->>` | 实线双向实心箭头（v11+） | 双向同步交互，两边互相等待 | 双向同步握手（很少用） |
| `<<-->>` | 虚线双向实心箭头（v11+） | 双向响应/回调返回（v11+） | 双向回调结果返回，几乎不推荐使用 |
| `-x` | 实线，末端带叉号 | **消息丢失 / 销毁消息**：消息发送出去，但无法送达；也用于触发对象销毁 | 网络丢包、实例销毁信号 |
| `--x` | 虚线，末端带叉号 | 响应丢失、返回失败 | 对方处理后，返回报文丢失 |
| `-)` | 实线，开放空心箭头 | **异步消息（发后即忘 fire‑and‑forget）**，发送方发完不阻塞，不用等返回 | MQ投递、事件总线、websocket推送 |
| `--)` | 虚线，开放空心箭头 | 异步事件的回调/通知 | 异步任务完成后的回调通知 |

```mermaid
sequenceDiagram
  participant A
  participant B

  A->B: "->" 实线，无箭头
  A-->B: "-->" 虚线，无箭头
  A->>B: "->>" 实线，有箭头
  A-->>B: "-->>" 虚线，有箭头
  A<<->>B: "<<->>" 实线双向箭头(v11.0.0+)
  A<<-->>B: "<<-->>" 虚线双向箭头(v11.0.0+)
  A-xB: "-x" 实线末端带叉号
  A--xB: "--x" 虚线末端带叉号
  A-)B: "-)" 实线开放箭头(异步)
  A--)B: "--)" 虚线开放箭头(异步)
```




### 激活
UML 时序图概念：**激活条（activation bar，细的竖矩形）**
- 激活：给参与者 John 画出一个**垂直的高亮矩形条**，代表：**这个对象正在执行、处于活跃、正在处理请求**。
- 停用激活：结束这个激活条，代表：**执行完毕，回到空闲状态**。

````
```mermaid
sequenceDiagram
  box 标准声明
    participant A as 小张
    participant B as 小李
  end

  box orange 语法糖
    participant C as 小王
    participant D as 小赵
  end

  box coral 激活堆叠
    participant E as 小孙
    participant F as 小周
  end

  A->>B: 早上好！
  activate B
  B-->>A: 早！
  deactivate B

  C->>+D: 早上好！
  D->>-C: 早!

  E->>+F: 早上好!
  E->>+F: 吃了没！
  F->>-E: 吃了!
  F->>-E: 好!
```
````
```mermaid
sequenceDiagram
  box 标准声明
    participant A as 小张
    participant B as 小李
  end

  box orange 语法糖
```
