## 使用传统npm方式安装可执行软件包

以创建 ``vite`` 项目初始化为例，
```
// 安装 create-vite 工具包
npm install create-vite --global
// 调用工具包的命令行工具初始化项目
create-vite my-app
```
当使用安装命令安装完成后，会在用户的 ``C:\Users\Administrator\AppData\Roaming\npm`` 目录的 ``node_modules`` 目录安装 ``create-vite`` 工具包，并在上层目录生成命令行文件 ``create-vite.cmd`` (CMD传统命令提示符终端调用文件)、 ``create-vite.ps1`` (PowerShell终端调用文件)、 ``create-vite`` (无后缀名文件，linux|macos系统调用文件)。
> + 能通过全局命令调用 ``create-vite`` 是因为 ``nodejs`` 安装时，已经将 ``AppData\Roaming\npm`` 自动添加到了环境变量中，命令行文件 ``create-vite.cmd`` 文件就在目录中。
+ 传统安装方式属于全局环境安装，如果要切换版本需要手动管理版本， ``npx`` 就不涉及卸载升级这种维护逻辑，工具自身维护不同版本，想用那个工具包的那个版本直接在命令行中注明版本即可，见下文。




## 使用传统npx方式安装可执行软件包

仍然以创建 ``vite`` 项目初始化为例

1. 第一种写法

```
npm create vite@latest
```
> 这里涉及一个语法糖映射关系， ``npm create vite`` 会被系统转换为 ``npx create-vite`` ，固定转换形式 ``create-xxx`` ，同时  ``create`` 也可以使用 ``init`` 替换 ``npm init vite`` ， ``create`` 语法糖是 ``npm`` v7+ 版本中被标准化用来执行初始化和脚手架的命令。

2. 第二种写法

```
// 直接跳过语法糖
npx create-vite@latest
```

> + 如果要在安装时指定包的仓地址 ``--registry=https://registry.npmmirror.com`` 的话，需要紧跟着 ``npx`` 关键字， ``npx --registry=https://registry.npmmirror.com creat-vite@latest`` ，如果放在后面，就会作为可执行包的命令行入参了。

<br />

**命令的执行逻辑**：以上两种写法都会在 ``npx`` 缓存目录安装 ``create-vite`` 包，并在安装完成后，会在当前包的 ``package.json`` 文件的 ``bin`` 配置项中进行精准查找 ``npx`` 执行是的命令 ``create-vite`` （现代的规范包都会在 ``bin`` 目录上写上  ``npx`` 的同名命令，e.g.  ``create-vite`` 包的 ``bin`` 配置项不仅写了精准匹配的 ``create-vite`` 命令，同时也保留了历史的命令 ``vca``，通过使用  ``npm view create-vite bin`` 可以查看。)，如果查找不到同名命令，就会退而求其次使用第一个配置命令执行。由于老的包可能没有对应的严格匹配的名字，e.g. ``@vue/cli`` 就会使用默认的第一个配置命令 ``vue`` 。

> ``npx`` 的缓存目录在 ``C:\Users\Administrator\AppData\Local\npm-cache\_npx`` 。




## 常用参数
+ -y: 遇到需要确认的命令时，默认使用  ``yes`` 。
+ -p: 安装多个包的时候需要使用 ``npx -p @vue/cli -p less`` 。
+ -c: 强制指定执行命令范围，多包安装时有用， ``npx -p @vue/cli -p less -c "lessc -v & vue -V`` 。




## 常用场景
+ 脚手架项目初始， ``@vue/cli``、 ``create-vite`` 等。
+ 测试某个包的不同版本，不影响当前项目的 ``package.json`` ，e.g. 使用不同的版本的 eslint 验证代码规范问题， ``npx eslint@8.0.0 src/ --ext .js .vue`` 。
+ 查看可执行包的执行命令版本，e.g. ``npx lessc -v``，安装 ``less`` 包后，会在内部的 bin 目录下有一个 ``lessc.cmd`` 的命令行文件， ``npx vue -V`` ，安装  ``@vue/cli`` 同样会生成 ``vue.cmd`` 。
+ 用不同的 ``nodejs`` 版本验证脚本， ``npx node@16.14.0 node test.js``，可以先通过 ``npm view node versions`` 查看有哪些版本。

> ``npx xxx`` 执行优先级: 如果当前目录存在可执行命令，也就是说当前项目文件夹的 ``node_modules\.bin\`` 目录下存在可调用的命令 ``xxx.cmd`` 就会直接输出当前项目下的调用结果，如果当前目录下不存在，就会查找全局目录下 ``C:\Users\Administrator\AppData\Roaming\npm\`` 下是否存在 ``xxx.cmd`` 文件，如果不存在，就会使用 ``xxx`` 名称去 ``npm`` 的配置仓 ``registry`` 查找是否存在 ``xxx`` 这样的包，以及是否存在 ``bin`` 配置，如果不存在就会报错 ``Error: could not determine executable to run`` 的错误。
