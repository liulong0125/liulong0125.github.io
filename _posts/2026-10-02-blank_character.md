## 零宽系列
**零宽系列空白字符都是不可见空白字符，用于排版（零宽系列字符都可以技术上用来绕过敏感词，前提是平台未做防范的化）。**

### 零宽排版标记
**零宽排版标记主要用于字符的断行、字形连字、合并。**
1. 零宽空格（\u200b）: 精准指定字符串的折断点进行精准换行。尽管 css 样式 `word-break: break-all;` 或 `overflow-wrap: break-word;` 都能实现文字折行不过是全局一刀切按照宽度剩余折行。

    | 特性 | overflow-wrap: break-word | \u200B 零宽空格 |
    |---|---|---|
    | 断行位置 | 浏览器自动随机切，不可控 | **开发者精确指定断点** |
    | 空白占位 | 无额外空白 | 不可见，不占宽度 |
    | 语义控制 | 无法区分“可以断/不能断” | 想在哪断就在哪标记，其余位置强制不折 |
    | 适用场景 | 普通文本段落 | 密钥、哈希、订单号、长ID、无分隔串 |
    | 缺点 | 乱切，破坏业务字符串视觉分组 | 需要预处理字符串插入\u200B |

    **扩展用途**
      + 用途1: 社交平台排版，强行换行/留空，也可以通过该字符和空格组合单独呈现一样，避免社交软件删除多余空行实现特殊排版。
      + 用途2: 大厂内部的 "文本数字盲水印"，将工号转换为二进制的 0 和 1 (按照字符的 Unicode 码点拆解)，**零宽空格**代表 0 ，**零宽不连字**代表 1，混入到段落中，复制的时候就会把看不到的字符也复制分享了，便于追踪。




2. 零宽不连字（\u200c）: 阻止两个字符自动连续，e.g. 阿拉伯语或某些连体**字形**（加和不加零宽不连字，字形完全不一样），以波斯语：**می‌بی**（意思：看见）为例。

    |  项目  |  带 ZWNJ（می‌بی） |  不带 ZWNJ（میبی） |
    | :--- | :---: | :---: |
    |  字符串  |  می‌بی |  میبی |
    | Unicode码点 | U+0645 U+06CC U+200C U+0628 U+06CC | U+0645 U+06CC U+0628 U+06CC |
    | 渲染效果 |  می‌بی（**ی 和 ب 中间断开，不连笔**，两个词素视觉分离） |  میبی（**ی 和 ب 自动连成一条连体曲线**，变成一整个连续字形） |
    | 含义说明 |  语法正确：前缀 `می` + 词根 `بی`（持续体标记） |  字形错误，字体自动把 `ی` 尾部和后面 `ب` 连接，变成单个连体串，不符合波斯语正字法 |

    > 有的地区比如伊朗（伊斯兰语/法尔西键盘）物理键盘上就有单独的 ZWNJ 按键，是日常高频输入键，波斯语大量需要控制字母连写。




3. 零宽连字（\u200d）: 强行将两个字符连接在一起。Emoji 组合就是用它实现的，e.g. 👨 + \u200D + 👩 + \u200D + 👧 + \u200D + 👦 → 👨‍👩‍👧‍👦（一家四口：爸妈 + 女儿 + 儿子），👨‍👩‍👧‍👦 对应的 js 字符串声明 `\uD83D\uDC68\u200D\uD83D\uDC69\u200D\uD83D\uDC67\u200D\uD83D\uDC66` ，虽然视觉上是一个字符实际上字符长度为 16。
> Emoji 的连接必须遵循 Unicode 联盟制定的官方规范，通过审批才能实线连字表情包效果。




4. 零宽不换行空格（\ufeff）: 禁止在标记处进行字符换行。
> 扩展用途: 此字符的原始用途基本废弃。Unicode 规范建议：**不要再把 \ufeff 当作零宽不换行空格使用**，它优先作为 [BOM(Byte Order Mark 字节序标记)](http://127.0.0.1:4001/%E5%AD%97%E7%AC%A6/2026/09/20/character_encoding.html#%E5%A4%A7%E7%AB%AF%E5%BA%8F%E5%B0%8F%E7%AB%AF%E5%BA%8F)，如果确实需要零宽不换行效果，改用 `\u2060`（Word Joiner，单词连接符）。




### Bidi 控制字符
世界文字分两种书写方向: 
1. RTL：从右往左（阿拉伯语、希伯来语）: 键盘依次按下希伯来字母伯来字母：א <- ב <- ג，字符序列在内存数组中的存储顺序从左到右[א ,ב ,ג]，页面渲染顺序 גבא。
2. LTR：从左往右（中文、英文、数字）: 键盘依次按下 a -> b -> c，字符序列在内存数组中的存储顺序从左到右[a, b, c]，页面渲染顺序 abc。

![blank_character_01.gif](/static/img/blank_character/01.gif)

依次输入 3 个希伯来字母和 3 个英文字母，可以直观的看到两种不同的书写方式，整个过程光标都是始终在字符序列的最后面，希伯来语的时候光标没有动是因为从右向左书写时左侧就是字符序列的最后面。


Bidi 控制字符（Bidirectional Formatting Characters，双向文本控制字符），主要用于文本阅读顺序、字符重排逻辑，**内存里存逻辑顺序（按键顺序），渲染时自动重排成视觉顺序**，解决同一段落同时包含 LTR（英 / 中文）与 RTL（阿拉伯、希伯来）文本的排版问题。

当一段文本**同时混有 LTR 和 RTL 文字**时，浏览器 / 编辑器 / 终端会用一套叫 **Unicode Bidi 算法**自动猜排版顺序（入门材料: [《UBA 基础：Unicode 双向算法入门》](https://www.w3.org/International/articles/inline-bidi-markup/uba-basics.zh-hans.html)、[《Bidi Unicode 控制字符使用问答》](https://www.w3.org/International/questions/qa-bidi-unicode-controls.zh-hans.html)）。

**Bidi不同类别的特性**

| 顶层分组 | 英文名称 | 核心含义 | 包含的Bidi缩写列表 |
| ---- | ---- | ---- | ---- |
| Strong | 强类型 | 自带固定阅读方向，作为Bidi算法的方向基准锚点 | L, R, AL, LRE, RLE, LRO, RLO |
| Weak | 弱类型 | 无独立方向，依附相邻字符，在W阶段完成重分类 | EN, AN, ES, ET, CS, NSM, BN, PDF |
| Neutral | 中性类型 | 无原生方向，N阶段根据邻近强字符继承方向 | B, S, WS, ON |
| Isolate | 隔离类型 | 创建独立Bidi隔离盒，切断盒子内外方向上下文传播 | LRI, RLI, FSI, PDI |

| 阶段 | 名称 | 执行时机 | 核心任务 | 关键行为 | 隐式模式（无Bidi控制字符） | 显式模式（含Bidi控制字符） |

| X | Explicit Rules 显式规则 | 第2步（P之后） | 维护嵌入栈/隔离栈，设置字符初始level | 遇到LRE/RLE/LRO/RLO/PDF/LRI/RLI/FSI/PDI，操作栈，覆盖初始level | ❌跳过，不运行 | ✅执行，Bidi控制字符在此生效 |
| W | Weak Rules 弱字符规则 | 第3步（X/P之后） | 修正Weak类字符Bidi_Class | 处理NSM、BN、EN、AN、ES、ET、CS；仅修改类型标签，不改动level | ✅执行 | ✅执行 |

| L | Lines Rules 行重排规则 | 第6步（I之后） | 生成屏幕绘制顺序 | 按行处理；从高level到低level遍历，奇数level反转Run内部字符顺序 | ✅执行 | ✅执行 |

**Bidi 控制字符就是一组看不见的零宽指令，用来<font color=red>干预</font>、<font color=red>引导</font>这套算法，手动指定文字方向、范围。**Bidi 控制字符分为两大类：**标记类**、**嵌入**、**重写类**、**现代隔离类**。
> 没有 Bidi 控制字符时，UBA（Bidi 算法）本身依然完整独立运行（隐式模式）；只是在混合 LTR/RTL 场景，自动推导的结果不一定符合人的预期。




#### 标记类
**1. 从左到右标记（LRM - Left-to-Right Mark，\u200e、&amp;lrm;）**: 插入一个标记，告诉 Bidi 引擎: **就近的文本基准方向是 LTR**，影响后面的弱类型的字符（一个简洁的基础例子: 阿拉伯语 - `الإصدار &lrm;1.2.0`，中文 - `版本 1.2.0` ）。

+ 隐式模式计算正确场景
    + 中文: `你好，Mr. Li! 很高兴见到你！` 。
    + 希伯来文: `שלום, Mr. Li! נעים לפגוש אותך!`。
    
  > 隐式计算逻辑
    1. 段落首字符：`ש`（希伯来字母，**强 RTL**）。
    2. Bidi 隐式判定：**整段段落基线方向 = RTL**。
    3. 分段渲染<br />
      1. `שלום,` : RTL 希伯来语，正常从右向左排。  
      2. `Mr. Li!` : 拉丁英文，属于 LTR 片段，嵌入在 RTL 段落内部，Bidi 会自动局部反转（放到右侧呈现）这个英文片段，英文单词顺序保持正确 Mr. Li。  
      3. `נעים לפגוש אותך!` : 后续希伯来语继续 RTL，**<font color=red>最终视觉顺序完全符合预期，不需要 LRM</font>**。

+ 隐式模式计算错误场景:
  + 中文: `房间 105, 房间 105`。
  + 希伯来文: `Room 105, חדר 105`。

  > 隐式计算逻辑
    1. 段落首字符：`R`（希伯来字母，**强 LTR**）。
    2. Bidi 隐式判定：**整段段落基线方向 = LTR**。
    3. 分段渲染<br />
      1. `Room 105, ` : LTR 拉丁英文 + ，正常从从向左排。  
      2. `חדר 105`&lrm; : 105 属于 EN 弱类型无独立方向，依附相邻字符，按照紧邻的希伯来语的 RTL，视觉呈现到了左侧（RTL 从右到左排版）。
    4. 纠错: 由于 105 视觉呈现到了左侧不符合语义，需要在希伯来语最后一个字符输入完成后通过增加一个 &amp;lrm; 标记影响后续的 105 弱类型字符，保持从左到右展示，再视觉上脱离了 RTL 布局保持语义，修正结果 `Room 105, חדר&lrm; 105`。




**2. 从右到左标记（RLM - Right-to-Left Mark，\u200f、&amp;rlm;）**: 插入一个标记，告诉 Bidi 引擎: **就近的文本基准方向是 RTL**，影响后面的弱类型的字符（原理同上，不过场景刚好相反，就不在赘述）。




#### 嵌入类
**1. 左到右嵌入（Left-to-Right Embedding，\u202a）**: 开辟一个新 Bidi 嵌入层级（embedding level），**主要用来修改该区域内中性字符的方向继承规则**；同时划定一个边界，**跨边界时弱字符的就近匹配不能穿透这个层级边界**。




**2. 右到左嵌入（Right-to-Left Embedding，\u202b）**: 逻辑同上。
> **结束 LRO/RLO/RLE/LRE 的方向控制（PDF - Pop Directional Formatting，\u202C）**: 栈弹出符，不是独立的开启标记。




#### 重写类
**1. 从左向右强制覆盖（LRO - Left-to-Right Override，\u202d）**: 强制**它后面所有字符**，无视字符本身的方向属性，**全部当作 “从左向右（LTR）” 渲染**（和 RLO 逻辑同理，参考 RLO 的具体示例）。




**2. 从右向左强制覆盖（RLO - Right-to-Left Override，\u202e）**: 强制**它后面所有字符**，无视字符本身的方向属性，**全部当作 “从右向左（RTL）” 渲染**。
 + 使用 RLO 强制定义后续文字的书写方式，e.g. 在希伯来语和英语混排的场景，直接在第一个字符定义 RLO 进行强制覆盖书写方式， `&#x202e;חדר 105 abc` -> &#x202e;חדר 105 abc&#x202C;，可以看到对于本身就是 RTL 的文字没有影响，对于非 RTL 字符全部进行强制翻转，105 也按照 RTL 方式呈现，依次输入 1 -> 0 -> 5，这几个字符就按照 RTL 渲染，就像希伯来语一样，导致了翻转渲染 501，以此类推，对 abc 也是。
 + 退出强制覆盖状态需要使用 `&#x202C;（PDF - Pop Directional Formatting）` 进行终止。
 + 该控制符最大的用途主要用在了木马欺骗，因为只是**视觉上反转显示，底层原始字符串不变**，e.g. 文件名 `test\u202egpj.exe` 在 windows 资源管理器中会显示为 `testexe.jpg`，常被用于木马伪装。
> **结束 LRO/RLO/RLE/LRE 的方向控制（PDF - Pop Directional Formatting，\u202C）**: 栈弹出符，不是独立的开启标记。




#### 现代隔离类
**1. 左向隔离（Left-to-Right Isolate，\u2066）**: 开启 LTR 隔离域；内外 Bidi 上下文隔离，不污染外部（替换 LRE）。




**2. 右向隔离（Right-to-Left Isolate，\u2067）**: 开启 RTL 隔离域；内外 Bidi 上下文隔离（替换 RLE）。




**3. 首强隔离（First-Strong Isolate，\u2068）**: 自动探测隔离块内第一个强字符，自动选择 LTR/RTL 隔离。
> 等价 HTML `dir="auto"`。

> + **隔离弹出符（PDI - Pop Directional Isolate，\u2069）**: 弹出 LRI/RLI/FSI 的隔离栈；**不能用来关闭 LRE/RLE/LRO/RLO**。
+ W3C/Unicode 推荐替代老旧 LRE/RLE/LRO/RLO，最大的区别在于老的写法如果没有写终止符持续影响后续文字，隔离类型的不会影响后续出现的强类型之后的字符（新的写法没有嵌入栈，不影响 level 的计算）。




### 其它杂项零宽字符
**1. 软连字符（SHY - SOFT HYPHEN，\u00ad、&amp;shy;）**: 条件零宽字符，非严格的零宽字符。不换行时宽度 = 0、看不见；**只有在这个位置发生换行时，才会渲染出连字符 `-`**。




**2. 蒙古元音分隔符（MVS - MONGOLIAN VOWEL SEPARATOR，\u180e、&amp;shy;）**: 条件零宽字符，非严格的零宽字符。**蒙古文专用的词内排版格式标记，零宽，只作用于传统蒙古文（胡都木蒙古文）字形塑形，蒙古文词尾元音字形变体、词内窄间隙，禁止换行。**。
> + Unicode 3.0 ~ 6.2：U+180E 被归类为 `Zs`（空白分隔符），标记为空白字符，很多旧文档因此把它当成空白 / 零宽空白。
+ **Unicode 6.3 重大修正**：改回 `Cf` 格式字符，撤销空白属性。
+ 渲染行为
  + **有蒙古文塑形引擎（Noto 蒙古体等）**: MVS 本身**没有独立字形、不占字符前进宽度**，但会修改相邻字母的字形变体，并在前后字母之间插入极窄间隙。
  + **无蒙古文支持的普通渲染器（普通文本框、简易编辑器）**: 直接忽略 MVS 标记，完全零宽、看不见，不产生任何间隙和字形变化。




## 空格分隔符
**1. 空格（Space，\u0020）**: 对应键盘的 `Space` 键。




**2. 不间断空格（NBSP - NO-BREAK SPACE，\u00a0、&amp;nbsp;）**: **把前后文字 “粘死”，浏览器 / 排版引擎不能在这个位置换行**，同时视觉上和普通空格一样。
> + 经典场景: **数字 + 单位** - 防止数字和单位被分到两行。
  ````
  ```html
  50&nbsp;kg
  200&nbsp;元
  30&nbsp;°C
  ```
  ````
+ **在 html 渲染环境中，可以使用此字符防止空格被折叠。**HTML 规范（HTML Living Standard）定义: 文本节点里的 **U+0020 空格、制表符 U+0009、换行 U+000A、回车 U+000D、换页 U+000C**，统称为**可折叠空白**。连续多个，会被合并为单个 U+0020；首尾空白会被剔除。而 **U+00A0（NBSP）不属于 HTML 可折叠空白集合**，所以不会被合并。
+ 又称作: **非截断空格**、**不换行空格**、**硬空格**。




**3. 全角空格/表意空格（Ideographic Space，\u3000）**: 普通半角空格 `U+0020` 只有半个汉字宽；U+3000 宽度和汉字一致，用于 CJK 正文里的等宽留白。
> + 中文 / 日文 / 韩文排版，汉字级空白。
+ 中文段落首行缩进（老式纯文本方案），纯文本（记事本、Markdown 无 CSS 缩进）里，**两个 U+3000 = 首行缩进两汉字**。现代网页优先用 `text-indent`，不推荐用全角空格做缩进。




**4. 半方空格（EN QUAD，\u2000）**: 表示当前字体的 1/2em 宽度（也就是字体高度的 1/2）留白，老式印刷半方块留白；现代几乎不用。
> + **<font color=red>em</font>** 是 `em-square` **字体设计用的虚拟画布 / 坐标网格**（设计阶段，字体内部），一套字体文件（ttf/otf）的 `head` 表里写死一个值（2048 / 1000）。CSS `font-size` 是对整张画布做**整体缩放**：`font-size:20px` → 整张 em-square 画布，缩放成边长 20px 的正方形（最终展示的时候，只有高度是一定是虚拟画布的缩放高度，宽度由 前进宽度 - advance width 决定。
+ **<font color=red>前进宽度（advance width）</font>** : 画完当前字符，排版笔向右移动的距离。单独存在于字体的 `hmtx`（水平度量表）来源是设计师手动设置，**和字形轮廓是两套独立数据**，也就是字体实际占用的视觉宽度距离。
  : 以字母 i 为例
  - ![blank_character_03.jpg](/static/img/blank_character/03.jpg)
  - LSB（左边距）= 151 （设计师设置）
  - glyph 矢量轮廓宽度 = 249（字体软件算出来的）
  - RSB（右边距）= 145 ，**不会存储，通过 `RSB = advanceWidth − LSB − (xMax − xMin)`**，`xMax − xMin` = glyph 矢量轮廓包围盒的水平宽度（glyph 包围盒 `xMin/xMax`）。
  - **这里的 LSB / RSB / glyph / advance 全部依然使用 2048 / 1000 这套全局坐标系的单位，单位是统一的。**
  - 反常识的场景
    - **<font color=red>字形可以宽度超出画布</font>**: 画布为 2048，glyph 为 4096，这个时候设置 LSB 为 -1024，advanceWidth 设置为 2048，这样渲染的字形会各占用前后字形 1024 个绘制空间造成字形重叠。
    - **<font color=red>字形完全可以花在画布外</font>**: 画布只是一个逻辑标尺，不是裁剪框，字即便是完全不在画布范围内，只要正确设置 LSB 和 advanceWidth 即可，那个 0 轴线仅仅是个逻辑坐标不涉及渲染结果，视觉上清晰的标识 2048 是多大的范围。
+ css 的 `font-size` 定义的字号大小是**字符的高度，不是宽度**。之所以汉字宽度和高度会一样，是因为汉字字形上属于方块字，绝大多数汉字字体都设置的是宽度 1em（也就是 advance width 和画布高度相等，个别字体未按照这个惯例设计），设计师字体设计的时候宽度是可以自己定义的，e.g. 常见的西文字 `Courier New`（等宽字体） 宽度是 0.6em， `Consolas`（等宽字体） 是 0.5em。
![blank_character_02.jpg](/static/img/blank_character/02.jpg)
+ 西文字体
  + 绝大多数西文字体都是不等宽字体，字母 i 很窄，w、m 就很宽，同一个字母大小写也会有宽度差异。
  + 即便是等宽西文字体，大写字母和小写字母也仅仅只是占用排版空间相同，字形差异仍然明显。
+ 中文字体
  + 绝大多数中文字体都是混合宽度字体，中文 1em 排版宽度，西文非等宽。




**5. 全方空格（EM QUAD，\u2001）**: 表示当前字体的 1em 宽度留白，老式印刷 1em 方块留白，历史排版遗存。
> 中文不要用，优先 U+3000，中文专用 1em 宽度留白符合规范 & 语义化。




**6. En 空格（EN SPACE，\u2002）**: 等效 `\u2000` - 半方空格，现代开发优先使用此字符。




**7. Em 空格（EM SPACE，\u2003）**: 等效 `\u2001` - 全方空格，现代开发优先使用此字符。
> 中文不要用，优先 U+3000，中文专用 1em 宽度留白符合规范 & 语义化。




**8. 1/3‑em 空格（THREE‑PER‑EM SPACE，\u2004）**: 当前字体的 1/3em 宽。
> 几乎没有业务场景




**9. 1/4-em 空格（FOUR‑PER‑EM SPACE，\u2005）**: 当前字体的 1/4em 宽。
> 无现代业务用途。




**10. 1/6-em 空格（SIX‑PER‑EM SPACE，\u2006）**: 当前字体的 1/6em 宽。
> 老式印刷微小间隙。示例：`A B`，无现代业务用途。




**11. 数字空格（FIGURE SPACE，\u2007）**: 和同字体数字 `0` 等宽。
> + 原始设计前提：**使用等宽表格式数字（tabular figures）**，此类数字 0 ~ 9 完全一样宽，比例字体（也就是非等宽字体）1，2，3 的宽度也有差异。
  + 等宽表格式数字不是所有字体都支持，需要字体本身内置两套数字字形：比例数字（proportional figures）+ 表格式等宽数字（tabular figures）。
  + 字体支持的前提下，需要使用 `font-variant-numeric: tabular-nums` 开启等宽表格式数字模式，当然现代网页只需要使用 css 开启字体模式就行，只需要设置一个 `text-align: right` 即可实现右对齐，非网页场景需要手动插入 U+2007（txt、markdown、pdf文本流、word）。
  + 网页端 css 右对齐无法实现的特殊场景: 行内混合文本，局部数字需要手动补齐空位，不能用整块`text-align:right`，需要手动插入。
  ```
  金额：  123.45
  总合计：45678.90
  ```
  + 生成固定宽度文本（例如打印、导出文本报表）输出产物是**纯文本字符流**，渲染阶段没有样式能力，对齐只能靠插入空白字符占位。
+ **数字表格、报表对齐专用，不能换行**。
+ **禁止用作千位分隔、单位间隔**，千位数字分隔优先使用 **U+202F NNBSP 窄无断空格**。U+2007 宽度等于数字 0，会显得空隙过大，排版难看。




**12. 标点空格（PUNCTUATION SPACE，\u2008）**: **宽度等于同字体下半角句号（U+002E `.`）的宽度**，源自老式热金属活字印刷，专门用来**占位替代半角标点**，实现表格内标点垂直对齐。
> + 半角标点也就是半角句号。
+ 场景示例: 当表格多行末尾有的行带句号、有的不带，用 U+2008 填充，让右边缘对齐。
```text
I saw a dog.
I saw a cat
```
+ 原理: 文比例字体里句号`.`本身字形窄；如果某一行没有句号，直接敲普通空格，宽度不匹配，上下对不齐。U+2008 直接复刻句号的前进宽度，作为 “隐形句号占位符”。
+ 用途: 这是**固定宽度文本流对齐**（老式活字、纯文本、DTP 手动排版）的技巧。视觉上第二行仍然是空白字符不会真的右侧对齐，解决左对齐排版，**书页最右边的裁切线整齐**（U+2008 要解决的原始印刷问题），活字排版，页面有固定版心，所有字符（包含空白占位）都算进版面宽度。印刷装订裁切时，沿着这条竖线裁，右边不会出现长短不一、毛边凹凸。




**13. 细空格（THIN SPACE，\u2009）**: 宽度约 ~1/5 em 或 ~1/6em。
> + Unicode 标准**没有强制死锁一个固定数值**，这是历史活字印刷遗留歧义。
+ 数字和单位之间做细微分隔 10&#x2009;kg、25&#x2009;%、37&#x2009;℃、100&#x2009;km/h。
+ 千位数字分组 123&#x2009;456&#x2009;789 （代替逗号做千分位分隔）。
+ 西文姓名缩写、首字母之间 J.&#x2009;D.&#x2009;Smith 缩写点后用细空格，比普通空格紧凑。
+ 法语排版：冒号、分号前的窄间隔（传统印刷） valeur&#x2009;: 100，现代法语规范优先使用 U+202F（窄不换行空格），防止标点被拆到下一行。
+ 公式、UI 界面、表格紧凑文本: 在不能使用 CSS margin/padding 的纯文本场景，制造很窄的视觉间隙。




**14. 发丝空格（Hair Space，\u200A）**: 宽度 1/10 em。
> + 紧贴字符之间做极微小间隙（印刷精细排版），当两个符号挨在一起，轮廓轻微碰撞、粘连，需要极细的隔离缝隙，又不想拉开太大距离。e.g. `f / i`、`] [`，两个符号紧贴会视觉粘边，插入发丝空格隔开。
+ 数学公式、符号组内微小隔离，比如多个数学符号相邻，需要一丝空隙，x&#x200A;∈&#x200A;ℝ。
+ 标点、引号邻接微调，e.g. 引号与相邻符号之间，增加几乎看不见的微小留白，消除笔画粘连。
+ **<font color=red>很多字体不自带 U+200A 字形！</font>**浏览器 / 渲染器会 fallback 到其他空格，宽度失效。




**15. 窄不换行空格（NARROW NO-BREAK SPACE，\u202f）**: **U+202F 没有 Unicode 标准强制固定的 advance-width，它的实际宽度，完全由字体里 U+202F 这个 glyph 的 AW（Advance Width，前进宽度）数值说了算**。
> + Unicode 文档只写：U+202F「视觉上应当和 U+2009 细空格一样窄」，**没有强制锁定固定的 em 分数**。但 U+2009 本身就允许 1/5em 或者 1/6em 两种实现，最终 U+202F 多宽，取决于字体设计师给 U+2009 写的 AW，再把 U+202F 设置成**相同 AW**。
+ 功能同 \u2009，只是不允许换行。



**16.中等数学空格（MEDIUM MATHEMATICAL SPACE，\u205F）**: 2/9 em 宽。**专门为数学公式排版设计，对应 LaTeX 里 `\:` 中等数学间隙**，普通正文排版几乎不用。
> + 二元运算符两侧的标准间隔（最核心）,数学公式中，运算符和操作数之间的留白。a&#x205F;+&#x205F;b、E&#x205F;=&#x205F;mc²。
+ 化学方程式，反应物、生成物、反应符号之间。2H₂&#x205F;+&#x205F;O₂&#x205F;→&#x205F;2H₂O。
+ 多因子、矩阵、数组内的中等隔离，公式内部需要比 thin space（U+2009）更宽，但远小于普通半角空格的间隙。
+ **<font color=red>它**属于数学专用空格**，不要拿到普通正文里用。正文的数字单位、缩写不要用 U+205F。</font>**




## 控制字符
**1. 水平制表符（HT - Horizontal Tab，\u0009）**: 对应键盘的 `Tab` 按键，光标跳到下一个制表位，默认编辑器一般每**8 列**一个制表位。它**不是固定宽度空白**，是一条指令：移动到下一个预设位置，视觉空白宽度可变。
> + e.g. 在第 2 列输入 Tab，直接跳到第 8 列；在第 7 列输入 Tab，也跳到第 8 列；水平制表符本身不会 “插入一串空格字符（U+0020）”，它只是一条控制指令；看到的空白是渲染器为了实现位置跳跃，在视觉上画出来的，文本流里并没有多出一堆 U+0020。
+ 通常编辑器为了代码缩进在所有编辑器环境中看到统一的视觉缩进，会支持敲击 Tab 按键后将这个指令替换为配置的对应的空格。


**2. 换行符（LF - LINE FEED，\u000a）**: **将光标移动到下一行（保留水平列位置不变）**。
> + 打字机典故：`Line Feed` = 滚筒带动纸张**向上卷一小段**，把已经打完的一行往上挪，**新的空白一行落到打字头下面**。；`Carriage Return(CR, U+000D)` 是回车，把滑架移到行首。
> + 文本分行，标记一行文本的结束: Unix / Linux /macOS（OS X 之后）默认行终止符：**LF（仅 U+000A）**。windows 是 CRLF = U+000D（CR，回车） + U+000A（LF，换行）。
+ 文本流解析
  + 很多程序按 LF 切分行：读到 U+000A，就认为当前行结束，开始新一行。
  + Windows 文件拿到 Linux 打开，行尾 CRLF 会多出一个 `\r`；Linux 文件在旧记事本打开，会挤成一整行（老记事本不识别单独 LF）。
+ 文本模式下
  + ```python
      # 打开阶段：选定文本模式
      fp = open("demo.txt", "w")
      # 写操作：此时标准库会做换行转换
      fp.write("hello\nworld")
      fp.close()
      ```
  + windows 写入`\n`，底层自动变成 `\r\n`；读取时，`\r\n`自动转回内存里的`\n`
  + Linux：写入`\n`底层就直接写`\n`，不转换。
  + 结论: **所以代码里统一写`\n`，不用手动拼`\r\n`。语言封装屏蔽了系统差异**。




**3. 回车符（CR - CARRIAGE RETURN，\u000d）**: 光标移动到当前行的最左侧（行首），不换行，不向下移动行。
> 部分协议（HTTP、FTP）: HTTP 协议头部规定：每一行必须以 `CRLF`（`\r\n`）结尾，这是标准强制要求。HTTP 头如果只用`\n`，部分老旧服务器会解析出错。




## 行分隔符
**行分隔符（LS - LINE SEPARATOR，\u2028）**: 强制换行，但不开启新段落。**不会产生段落间距、首行缩进**。解决传统 `CR(\r)/LF(\n)/CRLF` 在不同平台含义不统一的问题，给纯文本一套**独立、无二义**的换行语义字符
> + **JavaScript 字符串字面量不允许直接出现 U+2028 / U+2029**，会报语法错误（早期 ES 规范限制），必须转义 `\u2028`；JSON 同理。
+ 很多编辑器、终端**不原生渲染**，可能看不见，容易成为隐藏脏字符，造成解析异常。**遇到它，文本就**换到下一行**（这个效果是能看见的）。**




## 段落分隔符
**段落分隔符（PARAGRAPH SEPARATOR，\u2029）**: 结束当前段落、开启新段落，给纯文本提供「段落边界」的标准化标记。
> + 传统文本只用 `\n` / `\r\n`，含义模糊: 有时只是换行；有时代表一段结束，下一段开始。Unicode 引入 PS，用来**显式标记段落结束**：遇到 U+2029 → 当前段落终止，后面文字属于新段落，在支持它的排版引擎里，**不止换一行，还会应用段落排版规则**（段间距、首行缩进、Bidi 段落重置）。
+ **Bidi 双向文本（阿拉伯 / 希伯来文）非常关键**
  -  Bidi 算法规则：**U+2029 强制终止当前 Bidi 段落，重置双向排版上下文**。U+2028 只是行断开，**不会重置 Bidi 段落**。
  - LS (U+2028)：仅断行，Bidi 上下文保留，属于同一段落。
  - PS (U+2029)：结束 Bidi 段落，所有双向排版状态清零，新段落重新计算方向。




## 附录

+ **通用类别（GC - General_Category）**: Unicode 字符数据库（UCD）里给**每一个码位**标记的字符类型标签。
  + 格式: 个大写字母（顶层大类） + 1 个小写字母（子类别）。
  + 一共 7 个顶层大类
    - `L` Letter 字母。
    - `M` Mark 组合标记。
    - `N` Number 数字。
    - `P` Punctuation 标点。
    - `S` Symbol 符号。
    - `Z` Separator **分隔符**。
    - `C` Other **其它**（控制、格式、代理、私用区）。

  + 空白和控制相关分类

  | GC | 顶层大类 | 子类含义 |
  |---|---|---|
  | Zs | Z=Separator 分隔符 | Space 空白分隔符 |
  | Zl | Z=Separator 分隔符 | Line 行分隔符 |
  | Zp | Z=Separator 分隔符 | Paragraph 段落分隔符 |
  | Cc | C=Other 其它 | Control 控制字符 |
  | Cf | C=Other 其它 | Format 格式字符 |




+ 零宽排版标记
